# 设备发现原理、入库配对与排错

> 本文是 [README](../README.md) 的详细补充，解释**为什么有时找不到设备**、
> **新手机怎么第一次入库**、**个别厂商的坑**。日常使用不需要通读，遇到问题再来查。

## 一、它是怎么找到设备的

三条通道同时用，结果合并成一行：

| 通道 | 适用 | 需要手机做什么 | 重启后 |
|---|---|---|---|
| USB 序列号 | 所有开了 USB 调试的机器 | 插线 | 即插即用 |
| mDNS 广播 `_adb-tls-connect._tcp` | Android 11+ 的「无线调试」 | **配对一次** | 自动回来，端口变了也能找到 |
| 扫全子网 5555 端口 | 老机器的 `adb tcpip 5555` | 先用 USB 执行一次 tcpip | **失效**，要重插线再来一遍 |

所以：**一台从没配对过的手机，这里就是扫不到**——它既不广播 mDNS，也不监听 5555。
这是 Android 的安全设计，不是软件漏扫。配对一次之后，它就永久变成"纯无线设备"。

实测记录：`adb mdns services` 同时收到 3 条 `_adb-tls-connect._tcp` 广播，
其中两台手机**没有插任何线**，在选择器里各占一行（连接列显示「无线调试」），双击即投屏；
息屏导致画面全黑时，右键「唤醒屏幕」这个动作本身也是走 Wi-Fi 送达的。
无线端口每次重启都会变，但 mDNS 会自动跟到新端口。

> 两个例外：vivo/OriginOS 走不了上面这套（见「情况 C」）；另外「重启后自动回来」
> 只对部分机型成立，vivo 每次重启都要重新写一次开关——这一条也已由程序自动补上。

## 二、新设备入库（每台手机只做一次）

### 情况 A：Android 11 或更新

1. 手机：设置 → 关于手机 → 连点「MIUI 版本 / 内部版本号」7 次打开开发者选项
2. 手机：开发者选项 → **无线调试** → 打开
3. 手机：无线调试 → **使用配对码配对设备**（此时会显示一个 6 位码和「IP 地址和端口」）
4. 电脑：打开选择器 → 点 **配对向导** → 先填弹窗里那个**配对端口**（注意不是主端口），再填 6 位码
5. 完成。之后每次开机只要「无线调试」是开的，它就会以 `连接 = 无线调试` 出现在列表里，不用插线

> 验证过：平板的无线端口是随机的（例如 `192.168.1.x:4xxxx`），重启后会变，
> 但 mDNS 能自动找到新端口，所以入库一次就够。

### 情况 B：Android 10 或更老

只能走 tcpip，且**每次重启手机都要重做一次**：

1. 插 USB，手机允许调试
2. 电脑执行：`adb tcpip 5555`
3. 拔线，在选择器里点「刷新」（勾选「扫描子网」），它会被 5555 扫描找到
4. 想省事：可给手机装个 Magisk 模块或开机脚本自动执行 tcpip（本工具未内置此方案）

### 情况 C：vivo / OriginOS（实测）

这台机器上**根本没有「无线调试」这个页面**——不是开关是灰的，是 vivo 把整个界面删掉了：

```
adb -s <USB序列号> shell cmd package query-activities -a android.settings.WIRELESS_DEBUGGING_SETTINGS
→ No activities found
```

所以上面情况 A 的第 2、3、4 步都做不了，也永远等不到那个 6 位配对码。
但底层 AOSP 的 adbd 是完好的（`init.usb.configfs.rc` 里还留着原版注释
"Don't stop adbd if Wi-Fi ADB is on"），真正的开关是全局设置 `adb_wifi_enabled`——
被删掉的那个界面原本写的就是它。入库因此改成插着 USB 执行下面三条命令：

```
adb -s <USB序列号> shell settings put global adb_wifi_enabled 1
adb mdns services          # 从广播里读它的 ip:端口（随机的）
adb connect <手机IP>:<那个端口>
```

这三步（找串号、写开关、找端口、连接）需要手动按顺序执行，没有一键脚本
（当前 macOS/Windows 原生版**暂无**自动补开关逻辑，需手动操作）。

- **不需要配对码**：只要这台电脑曾经用 USB 授权过调试（公钥已进手机的 `adb_keys`），
  直接 `adb connect` 那个 TLS 端口就能连上。反过来，**一台新电脑没法给这台 vivo 配对**，
  因为配对码只存在于被删掉的那页里；换电脑时退回情况 B 的 `adb tcpip 5555`。
- **vivo 每次重启手机都会把开关打回 0**。实测：`adb reboot` 起来之后 `adb_wifi_enabled = 0`，
  mDNS 也不再广播它（其他一些机型会自动回来，不能类推）。端口每次还都不一样，
  所以端口只能现查，别记下来复用。
- **写开关的前提是那一刻 USB 线插着**——开关只能通过一条还活着的通道写回去，而手机刚重启时无线正是断的。
  所以第二节标题那句「每台手机只做一次」对 vivo 要打个折：入库确实只配一回，但手机每次重启后
  需要它短暂插一次线手动补开关（平时连着就不用管）。

## 三、四个会让设备"找不到"的坑

1. **网段不对 / 隔了一层 NAT**。如果电脑走的是「光猫 → 二级路由器」这种拓扑，而手机连的是光猫自己的
   Wi-Fi，两个网段之间隔着 NAT，mDNS 和子网扫描都过不去——表现就是"手机明明开着无线调试却搜不到"。
   让手机和电脑连**同一个路由器**就行。工具里的子网扫描只覆盖本机所在的那个 /24。
2. **手机省电把 Wi-Fi 睡了**。空闲时 ping 通要 56–90ms 就是这原因。投屏本身没问题，但第一次连接会慢几秒。
3. **mDNS 广播会自己飘走**。`adb mdns services` 读到的是一张快照，不是稳定表。实测 vivo 在
   `adb_wifi_enabled` 一直为 1 的情况下，连续 6 次采样（约 24 秒）都不在广播列表里，同期平板一直在；
   反过来刚打开无线调试时约 2 秒就会出现。所以"开关是开的"不等于"这一轮能扫到"，下一轮大概率又有了。
   看门狗因此先试缓存里记过的端口（`shared/devices.json` 的 `TlsLast`），不依赖这一轮广播。
4. **`adb connect` 成功不等于通道可用**。手机换了无线端口以后，旧端口会以 `offline` 的状态
   永久挂在 `adb devices` 里，直到 adb server 死掉。所以连上以后要看状态列是不是 `device`，
   是 `offline` 就得 `adb disconnect` 掉它，否则每翻转一次无线开关就多攒一个僵尸条目。
   （`adb disconnect` 不带参数是**无差别断开所有设备**，调试时要用 `adb disconnect <ip>:<端口>`。）

## 四、按键无效？小米/HyperOS 要额外开一个开关

「返回 / 桌面 / 多任务 / 唤醒」（右键菜单，以及两端导航条上的七颗键，含音量± 与息屏）走的是
`adb shell input keyevent`。在 **MIUI / HyperOS** 上，
仅开「USB 调试」不够，`adb` 注入按键会被系统以
`SecurityException: ... INJECT_EVENTS permission` 拒绝，表现就是**投屏/剪贴板都正常、唯独按键没反应**。
需在「开发者选项」里**额外**打开：

> **USB 调试（安全设置）**（"允许通过 USB 调试修改权限或模拟点击"，通常要求登录小米账号并插入 SIM 卡）

开启后按键即时生效。两端遇到这种拒绝都会**直接给出这条提示**而不是静默失败：Windows 在窗口顶部的横幅上，
macOS 在页面顶部。这是系统权限限制，不是本工具的 bug。
